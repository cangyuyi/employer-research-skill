# 职业画像、报告与文档交付

用户没指定格式时，先提供可用结论和证据，不自动做昂贵排版。用户要完整报告或PDF时再用对应部分。

## 职业画像

对每个可核验职业，尽量回答以下问题；缺失项写未公开／未核实，不填看似合理的企业事实。

| 维度 | 应保留的区分 |
|---|---|
| 名称、时效与工作性质 | 企业原职位名、序列／职级、历史／当届样本；不是当前空缺确认 |
| 任务或内容 | 企业JD与基于职业知识的分析分开，不能由标题补出完整JD |
| 学历、专业与技能 | 具体岗位条件与行业建议分开；本科、硕士、博士不混用 |
| 专业关联 | 直接对口、业务场景交叉、配套、推广；说明关联理由与缺口 |
| 薪资、福利与劳动条件 | 招聘标价／实际收入、单位、固定与浮动、适用范围、未知项 |
| 进入职业的决策 | 可以给决策框架；只有实际访谈才写“受访者当时如何选择” |
| 文化和规范 | 公开理念、JD要求、调查建议和实际内部制度分别标识 |
| 发展前景 | 行业依据与企业事实分开；不保证晋升年限、加薪或岗位增长 |

若用户给了个人背景，可做有依据的匹配分析；不要无依据量化适配分数，也不把个人偏好或条件写进永久技能。

## 报告骨架（可取舍）

1. 题名、对象、调查截止日、复核日与资料方法。
2. 摘要：关键发现、适合／不适合的方向、最重要的证据限制。
3. 企业画像：主体边界、核心业务、规模数据及口径。
4. 文化、用人标准、人才培养与公开劳动条件。
5. 用户要求的职业画像或岗位比较。
6. 薪酬与福利证据表：每个数字保留岗位和限定条件。
7. 职业选择框架、进入成本、机会与风险。
8. 未核实事项与真实访谈／HR书面核实提纲。
9. 来源索引；有审校时附实质变更与仍未解决事项。

使用“公开资料调查／非官方研究”等恰当身份，不伪装成企业授权出版物、员工访谈或审计报告。访谈提纲不等于已开展访谈。

## 修订交付

- 保留旧版与原始证据；新版使用可区分的文件名。
- 在正文实际修正，不只是另写“已提醒”。同步摘要、职业表、薪资表、引用映射及导出格式。
- 区分错误修正、来源冲突、范围限制、语言优化和未核实；不要把所有修改夸成发现造假。
- 删除无支撑作用的候选资料时也删对应断言依赖；将共享镜像替换为原始发布页不是新增独立证据。
- 记录本轮确实重新核验的范围；仅排版不更新事实调查日期或声称全面复核。

## PDF与Word：内容先于装饰

优先使用环境已有的文档库与可用技能，工具可替换，不绑定操作系统、字体绝对路径或某次项目。若提供工作区依赖定位工具，先定位运行时，不无端安装整套TeX或其他引擎。

可借鉴可靠开源模板的层级设计，但准确描述“参考设计”“复用模板”还是“实际使用该引擎”；不声称安装或执行了没有使用的技能／项目。用户未要求重新找工具时，不必每次联网寻找模板。

### 视觉与信息层级

- 对长报告保持统一页面、边距、标题、正文、表头和引文样式；颜色服务信息分类，不强制某个行业配色。
- 中文字体应覆盖实际字形，优先可靠嵌入；英文术语、数字和标点也要检查。文档使用系统字体不意味着应把字体文件随技能分发。
- 对历史／当届样本、企业自述／分析、薪酬限制给出明确标签，不能只靠颜色区分。
- 适合时做目录、书签和来源跳转；表格重复表头并避免一行断成两页。
- 不为漂亮图表补造数字，也不要把不可比工资画成排行。

### 必须实际检查的两条链

**文字链**：修订正文 → 来源编号 → 职业表 → 导出PDF／Word。核对正文段落、表格单元格、数字、单位、日期、链接及引用映射是否保全。提取文字可查遗漏，但不能证明数据语义正确。

**视觉链**：最终PDF → 渲染页面 → 查看整体分页图与关键页。检查缺字、黑方块、重叠、被裁切的表格、孤行、过小字号、不可见编号、页码、链接与大块意外留白。

可用PDFium、Poppler或环境已有渲染器；缺依赖时报告限制，不静默假称已看过渲染。缓存或字体配置报错先判断是否影响输出，控制日志和进程时间，遵守环境权限。

有自绘编号、页码、标签时隔离绘图状态；必要时显式重置文本上升量、绘制模式与颜色。**提取到文字不代表肉眼能看到它**，尤其是上标引用之后绘制的编号。

最后一次修改后再渲染／核查，不能把上一版截图当新版验收。仅在实际发生后说“通过检查”。

## 交付的最小充分集

主报告或用户指定文件＋关键限制＋可查看的来源。完整研究可附职业CSV、断言核验表、来源索引和修订说明；避免把构建日志、缓存和过时预览混进正式包。用户要可移交包时可纳入必要原始附件与文件清单，但不打包隐私或密钥。

使用可打开的实际文件路径／附件，不把内部工具引用ID或尚未生成的文件当成交付结果。

## 修订回归

给当前任务写“必须保留的限制”和“不能回流的撤回结论”，用`check_revision_consistency.py`检查实际交付提取文本。规则默认只用于report角色，audit角色可保留旧结论用于追溯。不会自动抽取PDF／Word，必须登记真实提取文件；字串规则不是语义审校。详见[evidence-schema.md](evidence-schema.md)。
